# jiojio厨房 · 点菜网页版 🍚

店主提供菜单（可标新上线/在售/已下线，可增删改），朋友登录后在菜单上勾选、约时间下单，吃完**逐道菜写评价**，店主收到订单并回复评价。

**零依赖**：不需要 `npm install`，只要服务器上有 Node（16 以上，建议 18+）。

## 一、拷到服务器并启动

```bash
# 1. 把整个 diancan-web 文件夹上传到服务器（scp 或任何方式）
scp -r diancan-web user@你的服务器IP:/home/user/

# 2. 登录服务器，启动
cd /home/user/diancan-web
node server.js
```

启动后：
- 网页地址：`http://服务器IP:3000`
- 仓库已带 `data/db.json`（含示例菜单与历史数据）；店主密码见其中 `config.adminPassword`，可手动改后重启。**该文件含明文密码，公开仓库请勿外传**

## 二、常用启动方式

```bash
# 指定端口
PORT=80 node server.js

# 后台常驻（关掉终端也不停）：最简单用 nohup
PORT=80 nohup node server.js > out.log 2>&1 &

# 或者用 pm2（可选，需先 npm i -g pm2）
pm2 start server.js --name diancan
pm2 save
```

## 三、安全组 / 防火墙放行端口

腾讯云控制台 → 轻量应用服务器（或 CVM）→ 防火墙 → 添加规则：放行 TCP 3000（或你设置的 PORT）。
云服务器本机如启用了 firewalld/ufw，也要放行对应端口。

## 四、（可选）用域名 + 80 端口

1. 域名解析 A 记录到服务器 IP
2. 用 nginx 反向代理：

```nginx
server {
    listen 80;
    server_name 你的域名;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
    }
}
```

> ⚠️ 提醒：中国大陆服务器上用域名对外提供网页服务，按工信部要求需要完成 ICP 备案；直接用 `IP:端口` 访问不受此限（但部分云厂商对未备案域名的 80/443 会拦截，IP 直连不受影响）。具体以服务器所在服务商与地区规则为准。

## 五、日常使用

| 谁 | 怎么用 |
|---|---|
| 朋友 | 打开网址 → 右上角「登录 / 注册」**注册一个账号（称呼+密码）** → 菜单上**勾选**菜品 → 「预约下单」→ 选日期时间、写备注 → 提交 → 吃完后在「订单」里**逐道菜打分写评价** |
| 店主 | 打开网址 → 底部「管理」→ 输管理密码 → 「订单」里接单/婉拒/标记完成 → 「菜品管理」里增删改、标新上线/下线 → 「评价」里逐条回复 |

**两套登录互不相干**：朋友账号在右上角登录（下单、写评价、取消订单必须登录，看菜单和看评价不用）；店主用管理密码在「管理」页登录。

- 菜品三种状态：**新上线**（菜单里带橙色标）/ **在售** / **已下线**（朋友完全看不到）
- **按菜评价**：订单完成后逐道菜打 1~5 星 + 选填一句话；每道菜每单只能评一次，漏评的菜下次还能补评；菜单上每行都有「★均分 / 暂无评价 ›」入口，点它进入**菜品详情页**，可看该菜的材料、价格和全部评价；没评价的菜显示空状态，点整行仍是勾选下单
- 朋友密码以加密哈希存储；登录态在本机保存 7 天
- **改店主密码**：编辑 `data/db.json` 里 `config.adminPassword`（明文存这个文件里，别泄露），重启生效
- **朋友忘记密码**：店主可在 `data/db.json` 的 `users` 数组里删掉该账号（nickname 对应项），让对方重新注册即可
- **备份数据**：复制 `data/db.json` 一个文件即可；恢复 = 放回去重启

## 七、数据说明

- 菜品状态：`new 新上线 / on 在售 / off 已下线`；朋友菜单只显示前两种，价格由服务端按菜品表重算
- 订单状态：`pending 待确认 → cooking 制作中 → completed 已完成`；待确认可被店主婉拒（可填原因）或朋友自己取消
- 只有「已完成」的订单能评价；评价按菜逐条记录（一条 = 某单某人对某道菜的星级+留言），店主可逐条回复
- 账号体系：`users` 存客人账号（昵称唯一、密码哈希）；`userTokens` 存客人登录态、`tokens` 存店主登录态，均 7 天有效
